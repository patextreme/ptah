# Proposal: pi-acp native MCP delivery

## Why

The carried pi-acp patch delivers ACP stdio MCP servers to pi only through the
`pi-mcp-adapter` extension's `--mcp-config` flag. The latest pi (0.99.0+,
currently 0.99.1) ships **built-in MCP** and rejects `--mcp-config` outright.
On a pi without the adapter installed, the patch's capability probe returns
false and drops ptah's `result_submit` bridge, so every `resultSchema` script
against the `pi` agent silently degrades to `result = nil`. The patch must
target pi's native MCP so typed results work without depending on a
third-party extension that now overlaps with core.

## What Changes

- Rework the pi-acp patch's delivery. Native path: register ACP stdio servers
  with pi's built-in MCP through a per-session extension generated by pi-acp
  that calls `pi.registerMcpServer(name, { …, exposure: 'direct' })`, loaded
  with `-e <ext>` and the per-session config path passed via
  `PI_ACP_MCP_CONFIG`.
- Capability detection: one cached `pi --help` probe selects the delivery —
  `--mcp-config` present (pi-mcp-adapter installed) → legacy adapter
  delivery, unchanged; `pi mcp` subcommand present (pi ≥ 0.99 native MCP) →
  native delivery; neither → warn and drop, unchanged.
- Preserve hygiene and existing behavior: per-session temp dir (config mode
  0600) removed on session dispose, stdio-only filtering, http/sse
  warn-and-drop, per-session isolation, no user-file mutation.
- Rewrite the patch's unit/component tests for both deliveries; extend the
  fake `pi` helper so `--help` can advertise either capability.
- Docs: update `nix/packages/pi-acp/README.md` — native MCP is the primary
  path; `pi-mcp-adapter` becomes a fallback for older pi, not a prerequisite.
- **No ptah crate changes.** The cargo suite stays untouched and fully
  offline. The pinned upstream pi-acp rev (0.0.34 / `b0581c9`) is unchanged.

## Capabilities

### New Capabilities

None — this change is packaging (a patched third-party adapter) plus docs. No
ptah behavior changes, so the change declares `skip_specs: true` in
`.openspec.yaml`.

### Modified Capabilities

None — `typed-results` and `agent-registry` behavior on ptah's side is
unchanged; the fix lives entirely in the patched adapter.

## Impact

- `nix/packages/pi-acp/mcp-config.patch` — rewritten (native delivery +
  capability detection + tests).
- `nix/packages/pi-acp/README.md` — prerequisites and mechanism updated.
- `.work/pi-acp` (gitignored) — development clone where the patch is authored
  and its suite is run; not committed.
- No flake input, rev, or hash changes; a `nix build .#pi-acp` output-path
  change only.
- Runtime: a pi with neither native MCP nor the adapter still degrades with a
  warning (`result = nil`), as before.
